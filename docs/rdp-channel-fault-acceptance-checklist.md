# RDP 通道与 HNP 真机故障验收清单

> 日期：2026-08-10
>
> 状态：ReadyForDeviceTest

本清单用于设备到位后的动作级验收。每项记录设备型号/系统版本、Windows 版本、连接方向、时间、诊断 JSON 文件名、关键日志和结论；没有证据时保持 `Pending`。

## 1. 基线

1. 安装同一次构建生成的 `common.hsp` 与目标设备 Entry HAP。
2. 主动连接前确认 Windows 的实际 host、TCP 3389、防火墙和 RDP 服务；应用应先显示端口检查，再进入 FreeRDP 协商。
3. 反向连接在 2in1 上确认 xrdp PID 和 3390 监听；tablet 不得存在服务入口、HNP 或 xrdp 进程。
4. 每组正常、失败、恢复动作后各导出一次诊断 JSON；检查其中没有 host、username、password 或访问码正文。

## 2. HNP 生命周期

| ID | 动作 | 通过标准 | 状态/证据 |
|---|---|---|---|
| HNP-01 | 应用启动，MSTSC 建立会话 | 单一 xrdp PID；3390 监听；画面、输入、剪贴板正常 | Pending |
| HNP-02 | 设置页点“停止服务” | MSTSC 断开；PID 与监听消失；UI 为 Stopped；重复停止幂等 | Pending |
| HNP-03 | 运行中对精确 PID 发 SIGKILL | 2 秒轮询内显示 Exited/退出码；可重新启动且 PID 唯一 | Pending |
| HNP-04 | 应用强停、窗口销毁、卸载 | 无孤儿进程和残留 3390 | Pending |
| HNP-05 | 上一正式版本覆盖升级，再回滚 | 配置兼容；无旧版本进程；包模块与 HNP 归属正确 | Pending |

## 5. 收口标准

- 每个动作至少有一次诊断 JSON 和对应日志时间窗；截图只作为交互补充，不能替代进程、端口或通道数据。
- 拒绝/占用/热拔插后必须执行恢复动作，不能只证明失败没有崩溃。
- `HNP-01`～`HNP-05` 全通过前，HNP 发布生命周期保持未 Verified；硬件相关 `CH-*` 未执行时继续标记 Pending。
